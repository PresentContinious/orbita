## Что за проект

**ОРБИТА 2** — песочница для наблюдения. Галактика из 5–7 звёздных систем, связанных коридорами. В каждой обитаемой системе на старте свой «плавильный котёл» из 2–3 цивилизаций: они растут, колонизируют, торгуют, позже воюют и плетут интриги. Игрок не командует — смотрит. Должно быть красиво, понятно и живо.

Старая версия (одна система, JS + canvas) — в ветке `main`. Новая пишется с нуля в ветке **`galaxy`**: TypeScript + PixiJS + React.

## Правила кода (коротко; полные — Global Constraints в плане)

- `src/sim/` — детерминированная симуляция без DOM/Pixi; никаких `Math.random()`/`Date.now()` — только `Rng` с зерном. Шаг 0.1 с.
- Деньги меняются только через `earn` / `spend` / `buy` в `src/sim/economy.ts`.
- Каждый корабль — отдельная сущность; никакой агрегации «флот = число».
- Сначала падающий тест, потом код. Весь `npm test` зелёный перед коммитом.
- Перед коммитом: `npm run codemap` (обновить карту кода).
- Коммит заканчивается строкой `Co-Authored-By: Claude <noreply@anthropic.com>` (или той, что задаёт твоя среда).

## Оркестратор: как исполнять план быстро и с проверкой

Главная сессия — **оркестратор**: раздаёт задачи и следит за качеством, сам код почти не пишет. Роли — в `.claude/agents/`:

- **implementer** (быстрая модель) — делает одну задачу плана: тест → код → проверки → коммит.
- **reviewer** (быстрая модель) — смотрит только дифф задачи против плана и Global Constraints; ответ PASS или FIX (≤ 5 пунктов, каждый с файлом:строкой и конкретной правкой).

Цикл одной задачи:

1. `implementer` с номером задачи → DONE + хеш коммита (или BLOCKED с диагнозом).
2. Автоматические ворота — уже внутри implementer: `typecheck` и весь `npm test` зелёные. Без этого ревью не зовём.
3. `reviewer` с номером задачи и хешем → PASS / FIX.
4. FIX → **тому же** implementer (продолжить его через SendMessage, а не запускать нового — контекст уже загружен). Одна итерация. Повторный FIX — оркестратор правит сам или спрашивает владельца.
5. Следующая задача.

Почему это быстро:
- в плане уже есть код — implementer переносит и проверяет, а не придумывает;
- ревьюер читает дифф, а не весь проект; что где лежит — по `docs/CODEMAP.md`;
- тесты — дешёвый фильтр до ревью; долгие проверки (`balance`, `smoke`) — только на вехах;
- исправления — в том же контексте, без перезапуска;
- задачи с непересекающимися файлами можно вести параллельно в отдельных worktree (например, задача 15 «камера» — параллельно с 9–14 «экономика»).

**Чтобы владелец видел, что происходит** (панель агентов, см. ниже):
- агентов называть по шаблону `T07 · implementer`, `T07 · reviewer` (поле `description` при запуске агента) — так они читаются в панели;
- на каждом переходе обновлять `docs/superpowers/progress.json` — одна строка на задачу:
  `"7": { "status": "review", "note": "коммит a1b2c3d" }`. Статусы: `active` (пишется), `review` (на проверке), `fix` (исправляется), `done`, `blocked` (тогда ещё `"reason": "…"`), без записи — «ещё не начато». Ключ верхнего уровня — имя файла плана без `.md`.

**Вехи** — после задач 6, 14, 18, 23: полный `npm test`, на 14 и 23 — `npm run balance`, на 18 и 23 — снимки экрана; ревью всей ветки более сильной моделью (reviewer с `model: opus`); короткий отчёт владельцу со снимками и цифрами.

## Панель агентов

`npm run panel` (нужен Python 3.9+, без библиотек) → http://127.0.0.1:8790. Читает журналы Claude Code этого репозитория прямо с диска и показывает:
- **Задачи** — все задачи планов из `docs/superpowers/plans/` со статусами из `progress.json`;
- **Таблица** — сессии, агенты, токены по участникам и по инструментам; клик по агенту — его **лента**: задание, что он пишет, каждое действие (команды, правки файлов) и результат;
- **Схема** — дерево: чат → конвейеры → агенты, кто работает прямо сейчас;
- оценку лимита на 5-часовое окно.

Обновляется каждые 5 секунд. Работает только локально (127.0.0.1). Перенесена из `BIMASTIL_WIFI/orquesta/herramientas/panel.py`.

## Идея на будущее: локальный ИИ на видеокарте владельца

У владельца AMD RX 9070 (16 ГБ). Возможный режим «советника»: локальная языковая модель (LM Studio / Ollama, сервер на localhost) принимает только **редкие стратегические** решения — объявить войну, вступить в коалицию, условия мира, предательство — и пишет летопись. Выбирает из вариантов, которые уже посчитал алгоритмический мозг, в формате JSON. Симуляция её **никогда не ждёт**: не ответила за несколько секунд — действует решение алгоритма. Руление кораблей, бой и экономика — только алгоритмы. Делать после подпроекта 3, когда у мозга будет интерфейс «варианты → выбор».
