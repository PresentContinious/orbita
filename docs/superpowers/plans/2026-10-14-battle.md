## Global Constraints

- Всё из Global Constraints плана этапа 1 остаётся в силе: `src/sim/` без DOM/Pixi/React, без `Math.random()` и `Date.now()`; `rng.fork(label)` — только с уникальной меткой (`'battle:' + id`, `'admiral:' + id`), никогда с постоянной меткой на каждое событие; шаг `SIM_DT = 0.1`; деньги только через `earn` / `spend` / `buy` в `economy.ts`; каждый корабль и каждая машина — отдельная сущность в `w.ships`; тексты интерфейса на русском; `npm run codemap` перед коммитом; коммит без упоминаний Claude/ИИ; ветка `galaxy`; без `git push` без разрешения владельца.
- **Все числа боя — в одном месте:** `src/sim/combat-config.ts` (рамка, бой, характеры, снаряды, урон, крыло, док, режиссёр) и таблица классов `src/sim/classes.ts`. В `config.ts` — только `ShipKind`, `SHIP_KINDS` (с полем `turn`), конверт `war`, `EVENTS.battleLog`, `UNIT_CAP`. В коде боя литералов-чисел из спеки быть не должно — арена крутит константы.
- **Порядок обхода фиксирован:** флоты по индексу в `w.fleets` (создаются по возрастанию id), корабли по индексу в `w.ships`, снаряды по индексу в пуле. Цели выбираются расслоённо: корабль выбирает цель на шаге, когда `ship.id % 10 === w.tick % 10`.
- **Ссылки по id.** Внутри шага корабль может умереть (`alive = false`), массив сжимается один раз в конце фазы кораблей (`compactShips`). Всё, что помнит корабль между шагами, хранит `id` и ищет через `w.shipIndex: Map<number, number>` (индекс в `w.ships`, перестраивается при сжатии и при `spawnShip`). Держава — через `w.civIndex`.
- **Запрет на тараны/метания — измеряется, а не декларируется:** арена считает минимальную дистанцию корпусов, срабатывания push-out, смены `D*`, время капитальных вне слота. Решения о движении — только у рамки (адмирал) и у слота; корабль сам никуда не «отходит», кроме горения по своей колонне.
- Свои корабли и свои обломки **прозрачны** для лучей, ракет и трассеров; чужие корабли, машины, обломки, камни и чужие торпеды — препятствия.
- Производительность: цель «тяжёлый ангар» ≤ 6 мс на шаг (задача 21). Никаких аллокаций массивов в горячих циклах — пулы и `scratch`-буферы на уровне модуля.
- Машины носителя рулят **без расталкивания** (`separate` и push-out их не трогают); корабли в рамке — без `separate` (только push-out из `fleet.ts`).

## Review Focus

Ревьюер смотрит сквозь все задачи:

1. **Детерминизм:** всё случайное в бою — из `battle.rng = w.rng.fork('battle:' + battle.id)`, у адмирала — `w.rng.fork('admiral:' + id)`; ни одного `Math.random`/`Date.now` в `src/sim/`; порядок обхода — по индексам, не по `Map` с разнородными ключами. Тест — задача 9 («одно зерно — один журнал боя»), задача 14 (арена дважды — побитово одинаковые позиции на 3 000 шагов).
2. **Деньги только через `economy.ts`:** покупка кораблей и машин — `buy(civ, 'warship' | 'fighter', …, 'war')`, лом — `earn(civ, v, 'salvage')`, ремонт бесплатный (казна не трогается). Инвариант журнала в тестах задач 1, 13, 22.
3. **Каждый корабль — сущность:** нигде нет «флот = число»; `Fleet.shipIds` — только список id; матрица исхода считается по живым кораблям, а не по сохранённым суммам.
4. **Запрет на тараны/метания проверяется метриками арены** (задачи 3, 7, 14): минимальная дистанция ≥ 2 длины, push-out на проход по колонне = 0, смен `D*` ≤ 4, капитальные вне слота ≤ 10 % времени. Изменение скорости любого корабля за шаг ≤ `accel · SIM_DT` (задача 7).
5. **Свои прозрачны для луча и трассера** (задача 4): луч, пересекающий свой корвет, бьёт чужой линкор за ним; корвет на пути чужой торпеды принимает её.
6. **Производительность:** в горячих циклах нет `filter/map/find` по `w.ships`, поиск соседей — только через сетки (`w.grids`, `w.projGrids`); выбор целей расслоён; «тяжёлый ангар» ≤ 6 мс (задача 21).
7. **Приказы с причинами:** каждая смена приказа и канала — строка в `battle.log` с текстом причины и запись `Fleet.orderReason`; приказ держится ≥ 20 с (бросок/отход 30 с), внеочередной — не чаще 10 с (задача 10).
8. **Код против реального кода:** имена и сигнатуры существующих функций (`steer`, `planetGoal`, `gateGoal`, `spawnShip`, `pushEvent`, `buy`, `SpatialGrid.query`) не меняются, кроме явно перечисленных в задаче 1 (`shipUpkeep(civ, ship)`, `shipPrice(civ, kind: ShipKind)`).

  const base = kind === 'caravan' ? ECON.caravanPrice : kind === 'miner' ? ECON.minerPrice : kind === 'colony' ? ECON.colonyBase : CLASSES[kind].price

/** содержание класса для ещё не купленного корабля (варианты бота) */
export function shipUpkeepOf(civ: Civ, kind: ShipKind): number {
  return SHIP_KINDS[kind].upkeep * (civ.shipyard ? ECON.shipyardUpkeepMul : 1) * (1 - RESEARCH.logistics.perLevel * civ.research.logistics)
}

/** содержание конкретного корабля: консервация ×0.3, машины 0 (через носитель), сироты — как корвет ×0.5, носитель +0.01 за машину */
export function shipUpkeep(civ: Civ, ship: Ship): number {
  const c = ship.combat
  if (!c) return shipUpkeepOf(civ, ship.kind)
  if (c.wing) return c.wing.phase === 'orphan' ? WAR.orphanUpkeep : 0
  let u = shipUpkeepOf(civ, ship.kind)
  if (c.hangar) u += WAR.craftUpkeep * c.hangar.craft
  if (c.mothballed) u *= WAR.mothballMul
  return u
}

- `assignSlots(w, fleet)`: живые корабли по ролям `CLASSES[kind].role`; линкоры (`line`) сортируются по боковой координате относительно `fleet.heading` и получают колонны `k = −⌊n/2⌋ …` монотонно; при `formation: 'double'` чётные — ряд `rows.line`, нечётные — `rows.second` с `y + grid/2`; фрегаты — `rows.frigate`, `y = k·grid + grid/2`; носители/снабженцы/десант/разведчики — `rows.rear`; катера — `boat`, `y = ±(W/2 + wingPad)`; резерв (`fleet.reserveIds`) — `rows.reserve`, `y = ±(W/2 + reservePad)`; корветы — `slot.kind = 'oval'`, `column = ±1` (крыло), `phase` равномерно по числу корветов крыла; флагман — центр широкой линии или второй ряд центральной колонны; `fleet.columns`, `fleet.width` пересчитываются; `fleet.reassignAt = null`.

- `markDamaged(fleet, ship)`: слот → `damaged` той же колонны (линкор) или полуколонны (фрегат, носитель); обратный `clearDamaged`.
