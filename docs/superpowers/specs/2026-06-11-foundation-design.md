# ОРБИТА — Этап 1 «Фундамент»: дизайн

Дата: 2026-06-11. Статус: утверждён пользователем (порядок этапов и UI-решение «обе панели рядом»).

## Контекст

ОРБИТА — zero-player песочница (React + Vite + canvas 2D): боты-государства развивают планеты, торгуют, воюют; игрок наблюдает и вмешивается «инструментами бога». План развития: 1) фундамент → 2) причинная дипломатия и читаемость → 3) глубокая война → 4) экономика и пираты → 5) несколько звёздных систем.

Этот документ — спека этапа 1. Цель этапа: симуляция, идентичная на всех скоростях; удобные скорости; код, готовый к росту; исправление известных багов; панели UI не конфликтуют.

## Объём

Входит:

1. Фиксированный тик логики цивилизаций.
2. Скорости ×1 / ×2 / ×5 / ×10.
3. Разбивка `src/solar/civ.js` на модули без изменения поведения.
4. Багфиксы: корабль-призрак, повторяющиеся цвета, утечка отношений мёртвых государств, колонизация от столицы.
5. UI: карточка планеты и панель дипломатии видны одновременно (рядом).

Не входит (следующие этапы): причины войн, матрица отношений, военные цели, экономика зон, контрабанда, мульти-системы, изменение баланса войны (включая разрушитель планет).

## Дизайн

### 1. Фиксированный тик симуляции

Проблема: `engine._update()` вызывает `civ.update(h, dt)` один раз за кадр с полным куском симуляционного времени `h = dt × timeScale`. На больших скоростях рулёжка теряет инерцию (`k = min(1, h·2.2) → 1`), ПВО-перехват проверяется слишком редко относительно пройденного пути ракеты, вероятности `random() < h·x` насыщаются. Поведение игры зависит от скорости и FPS.

Решение — аккумулятор фиксированных тиков в `Engine._update`:

- Константа `CIV_TICK = 0.05` (20 тиков на симуляционную секунду).
- `this.civAcc += h; while (this.civAcc >= CIV_TICK) { this.civ.tick(CIV_TICK); this.civAcc -= CIV_TICK }`.
- Защита от спирали смерти: не больше `ceil(0.05 × 10 / CIV_TICK) = 10` тиков за кадр (бюджет максимальной скорости при кадре 50 мс); излишек времени не копится (сбрасывается), игра в худшем случае слегка замедляется, но не зависает.
- Визуальные эффекты, затухающие и на паузе (лучи `beams`), переезжают в `civ.updateVisual(dt)` — вызывается раз в кадр с реальным dt, как сейчас.
- Сигнатура `civ.update(h, dt)` заменяется на `tick(CIV_TICK)` + `updateVisual(dt)`; других вызывающих нет.

Физика (`_step`, подшаги ≤ 0.02 с, потолок 40 подшагов за кадр) не меняется: при максимальной скорости ×10 и кадре 50 мс нужно 25 подшагов — в бюджет укладывается, туннелирование снарядов уходит вместе с ×50.

Внутри `Civ.tick` существующие таймеры (`decideT`, `relTick`, `astTick`, `missileT`, перезарядки ПВО) продолжают работать как есть — они и так считают симуляционное время; меняется только размер и регулярность шага.

### 2. Скорости

В `App.jsx`: `SPEEDS = [×1, ×2, ×5, ×10]` (значения 1, 2, 5, 10). Кнопки и горячая логика не меняются.

### 3. Разбивка civ.js на модули

`src/solar/civ.js` (1754 строки) превращается в каталог `src/solar/civ/`:

| Файл | Содержимое (перенос как есть) |
|---|---|
| `index.js` | класс `Civ`: состояние (`states`, `ships`, `asteroids`, `events`, `beams`, `rel`, таймеры), `reset()`, `tick()`, `updateVisual()`, `log()`, справки для UI (`summary`, `missionText`, `shipAt`, `astAt`, `shipLabel`), хуки движка (`onPlanetHurt`, `onPlanetLost`, `onWarheadHit`), отрисовка (`drawUnder`, `drawOver`) |
| `constants.js` | `SHIP`, `STATE_COLORS`, `PIRATE_COLOR`, `WAR_AT`, `ALLY_AT`, `TAU`, `SQ`, хелперы `clamp/rand/pick/dist` |
| `diplomacy.js` | `relKey/getRel/setRel/isWar/isAlly`, `_diplomacyDrift`, оборонительные союзы, `_maybeSpawnPirates` |
| `economy.js` | `_populations`, ПВО-перезарядка/стройка, торговля и караваны, колонизация, шахтёрская логика, астероиды (`_spawnAsteroid`, `_asteroidsTick`) |
| `warfare.js` | `_stateDecide` (военная часть: тактики, осады, десанты, залпы), `_launchWarhead`, `_pvoIntercept`, `damagePvo`, `_planetDefense` (ополчение), `_planetFalls` |
| `ships.js` | `_spawnShip`, `_steer/_steerPlanet/_holdOrbit/_formationSlot/_leadPoint`, `_ships` (миссии и бой), `_attackRun`, `_fire`, `_damageShip`, гибель и трофеи |
| `pirates.js` | `_pirateDecide`, эвакуация базы, захват дредноутов и грабёж (части обработчика гибели, относящиеся к пиратам) |

Механика переноса: модули экспортируют функции, принимающие `civ` первым аргументом (`export function diplomacyDrift(civ, h) {...}`); класс `Civ` в `index.js` хранит всё состояние и делегирует. Публичный API для `engine.js` и `App.jsx` не меняется: `engine.civ.events`, `.asteroids`, `.ships`, `.summary()`, `.stateById()` и т.д. работают как раньше. Поведение игры не меняется вообще — чистый перенос кода.

`_stateDecide` на границе economy/warfare делится так: мирная ветка (торговля, колонизация, сецессия, охота на пиратов, мирное ПВО) — `economy.js`; военная ветка — `warfare.js`; сам диспетчер решений остаётся в `index.js`.

### 4. Багфиксы

1. **Корабль-призрак.** `_spawnShip` не добавляет корабль при `ships.length ≥ 130`, но вызывающие уже списали кредиты и навешивают миссии. Фикс: `canSpawnShip()`-проверка (или возврат `null` и проверка у всех вызывающих) — деньги списываются только если корабль реально создан.
2. **Повторяющиеся цвета.** Выбор `STATE_COLORS[states.length % N]` после смертей/сецессий даёт дубли. Фикс: выбирать наименее используемый цвет среди живых государств.
3. **Утечка дипломатии.** Записи `rel` и `warSince` мёртвых государств живут вечно. Фикс: при удалении государства вычищать его ключи.
4. **Колонизация от столицы.** Кандидат сортируется по дистанции от `myPlanets[0]` (случайный порядок массива). Фикс: считать от столицы (`st.home`, с фолбэком на первую планету).

### 5. UI: панели рядом

- В `App.jsx` убирается условие `!showDiplo` у карточки планеты: `{sel && (...)}`.
- Когда открыты обе панели, они стоят рядом у правого края: дипломатия на своём месте, карточка планеты левее неё (CSS: модификатор `.panel.with-diplo { right: <ширина дипломатии + отступ> }` или flex-контейнер правой колонки).
- На узких экранах (< ~900 px) панели складываются в столбик либо карточка поверх — допустимо простейшее решение, главное «обе достижимы».

## Критерии приёмки

1. `npx vite build` проходит; `npm run dev` — игра выглядит и ведёт себя как раньше на ×1.
2. На ×10 за равное симуляционное время (например, 5 минут симвремени) картина сопоставима с ×1: войны не учащаются, ПВО перехватывает так же, бои не «телепортируются». Проверка наблюдением + лентой событий.
3. Скорости ×1/×2/×5/×10 переключаются, пауза работает.
4. Клик по планете при открытой дипломатии показывает карточку планеты; обе панели видны и закрываются независимо.
5. Поведение после разбивки на модули идентично (та же игра, никаких новых механик).
6. Багфиксы: казна не уменьшается при недостроенном корабле; у живых государств нет одинаковых цветов (пока цветов хватает); `rel`/`warSince` не содержат ключей мёртвых государств; колонисты летят к ближайшей от столицы планете.

## Проверка

Тестовой инфраструктуры в проекте нет; для этапа достаточно ручной проверки по критериям выше (dev-сервер, наблюдение на ×1 и ×10) плюс зелёный `vite build`. Юнит-тесты отложены: им потребуется выделение чистых функций из движка, что разумнее делать по мере этапов 2–3.
